# 输入归一化验证（2026-10-21）

`Input.text` 的常见路径原先会对 UTF-8 输入再次执行 `encode(UTF_8)`，并在 LF 正文上执行无匹配的 `gsub`。现在跳过相同编码的转换，在没有 CR 时跳过替换；需要修改时只操作归一化过程拥有的副本。返回值仍可变且独立于调用方；原文、编码策略、逻辑 NUL 校验和转码前字节预算不变。

在 macOS arm64、Ruby 4.0.6 上使用 `benchmark/input.rb`，对修改前的 `b8746d9` 与本次源码执行相同脚本。每轮重复归一化同一正文 30 次，共三轮；语义和对象所有权断言在计时外执行。下表是三轮中位数，属于重复输入的本地微基准，不代表设备采集、完整配置解析或网络吞吐。

| 正文 | 输入字节 | 修改前耗时 | 修改后耗时 | 修改前分配 | 修改后分配 |
| --- | ---: | ---: | ---: | ---: | ---: |
| UTF-8 / LF | 950000 | 67.354 ms | 0.866 ms | 120 | 30 |
| UTF-8 / CRLF | 1000000 | 177.798 ms | 162.056 ms | 150 | 150 |
| ISO-8859-1 / LF | 850000 | 169.909 ms | 90.748 ms | 150 | 60 |

复测当前代码：

```sh
bundle exec ruby -Ilib benchmark/input.rb
```

比较基线时，把目标提交的 `lib/ctx_parser/input.rb` 放入独立临时目录的 `ctx_parser/input.rb`，然后使用 `bundle exec ruby -I<临时目录> benchmark/input.rb`。脚本输出实际加载的 Input 来源，避免误测已安装版本。不要覆盖工作区文件来切换基线。
